# Changelog

- Keep the format the changelog already follows: heading shape, category names and their order, and the unreleased section. A new changelog follows [Keep a Changelog 1.1.0](https://keepachangelog.com/en/1.1.0/) and SemVer.
- Add pending changes under the unreleased section at the top.
- An entry says, in one line, what changed for whoever uses or installs the project. A change they cannot notice stays out: refactors and internal optimizations without a visible effect, tests, CI, development fixtures, and development-only dependencies.
