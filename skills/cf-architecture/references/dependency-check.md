# Dependency Check

Check the target tree's dependencies when a SCIP indexer for the code's language runs here (`rust-analyzer scip`, `scip-typescript`, `scip-python`, or the one for that language). Write the index outside the repository; write, also outside it, a file that assigns the current code to the tree's modules, with the form's groups in the order of its direction; run the bundled `scripts/tree-check.mjs`, resolved from the active skill root and never from the project working directory, with the index and that file: its first lines give the file's format and what it reports. Correct the tree until it reports no cycle, no use against the direction and no unassigned code; when one element causes a use, move that element, not its file. When the tree adds a port so that a module stops naming an element of another, declare it with a `port` line that names the port instead; every port the script lists appears in the tree under that name, with the condition in `Boundaries` that justifies it. When no indexer runs, say under the tree that its dependencies are not checked, name the indexer that would check them, and ask the user whether to run it. On a yes, take the command from the indexer's own documentation, searched online, not from memory; prefer a form that runs it without installing it, and when it installs, say where before running it.
