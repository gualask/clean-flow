# cf-cognitive Flow

## Purpose

Document the runtime flow for `cf-cognitive`, the public local cleanup entrypoint for reducing real cognitive complexity in source files.

## Runtime Inputs

- Public skill: `skills/cf-cognitive/SKILL.md`, which carries all three flows in its own body since 2026-08-16
- Runtime references: none of its own
- Shared sources vendored into runtime paths: `skills/_shared/references/navigation-cost.md`
- Target artifacts: none

## High-Level Flow

1. Start from the requested file target or discovery area.
2. Choose discovery, evaluation, or execution from the current request; each flow names its trigger in one parenthesis. There is no ambiguity question (removed 2026-10-24): on a bare file path gpt-6.1-sol chose evaluation and edited nothing (1 of 1); "Choose exactly one flow; if … ambiguous, ask one focused question instead of choosing" asked 2 of 2, and the same sentence as a loose paragraph asked 0 of 1. The read-only default does no harm and costs no turn. Also removed without a measured loss: "Do not infer execution from words like 'review'" (no evaluation or discovery run edited, 0 of 6).
3. Read `navigation-cost.md`; it owns hard-trigger values, exemptions, remedies, and the report/action rule. Every flow first runs a command that prints each function's logical lines and deepest nesting. Nesting counts every control block, including an `if` that only guards a `break`: on linqode `liveRows` (`for` → `if` → `if` with `break`) targeted evaluation named the nesting 0 of 5 without that line and 3 of 4 with it (2026-10-06); 1 of 1 on gpt-6.1-sol (2026-10-24). The measure prints the functions ranked by nesting then length, at most 30: one run without a cap printed its whole output once, about 36k tokens; with it every measure output stayed under 2k (4 of 4, 2026-10-25). An `else if` continues its chain and adds no level, as in Cognitive Complexity (Campbell, SonarSource whitepaper: `else if`, `elif` and `else` take a hybrid increment with no nesting increment, "because the mental cost has already been paid when reading the if") and in ESLint `max-depth` (an `if` that is another `if`'s alternate pushes no block). A measurer that counted each link as a level ranked two `else if` chains first, one of them a 7-line function, and found 1 of 3 target functions on sidekyk; with the line 3 of 3 in 4 of 4 runs (2026-10-25). The measurer is built on a parser the project already has, in its dependencies or in the language's standard library: without that line one run of two searched the machine's pnpm store and its sqlite index outside the project (one output of about 50k tokens, 583k input); with it 0 of 2 left the project and both used about 355k input against a cell median near 400k, though they spent 5–6 search commands against about 4 in the clean run without it (2026-10-25).
4. In discovery, run the measure over the area's source files, rank at most three functions, not files, by nesting then length, and do not edit. Without "nesting depth" two functions three levels deep in linqode `internal/logs` were missed with all files read (0 of 1, 2026-10-06); with it, 2 of 2. The shortlist lines on weak candidates, empty lists, and keeping hard-trigger candidates were dropped on 2026-10-24 (3 of 3 found without them). `repo-tree.mjs --largest 15` was dropped from discovery on 2026-10-23: on sidekyk the full skill with it found 0 of 3 target functions in 2 of 2 runs, while the measure over the area found 3 of 3 in 5 of 5 runs (two before the four tests, three with them).
5. In evaluation, judge the named files and do not edit; past a hard trigger, `optional` or `keep as-is` needs a named exemption (`recommended` came out 3 of 3 without a separate default line, 2026-10-24).
   In both, a file past the file-length trigger gets the file-length verdict, defined once above the flows: `route` to `cf-placement`, or the named exemption that justifies its size. A `cf-cognitive first` branch (slim long functions, then measure again) was tried and removed (2026-10-05): slimming in place grew the 302-LOC fyler-ui hook to 309–353 LOC in 3 of 3 runs, so it always ended in a file split, and in discovery it also covered a 330-LOC model with distinct responsibilities. The split pieces of that hook were 82–114 LOC.
6. In execution, measure the target and keep behavior stable; stay inside the file. There is no no-edit guard (removed 2026-10-24): on linqode `catalog.go` (functions up to 13 lines, nesting ≤1) "Simplify" was edited 1 of 2 without it (a correct `sortedKeys` rewrite, tests green) and 0 of 2 with it; under an explicit request a correct small edit is not harm. On gpt-6-luna it was edited 2 of 2 without a prior measurement and 0 of 2 with it (2026-10-06).
   `local-refactor-rules.md` left the skill on 2026-10-24: the four tests in the body carry its rules, and one of its lines (side effects visible at the call site) contradicts **owner**. Without it the lifecycle cell (sidekyk `useContentSearch`) met 5 of 5 shape conditions (4 of 5 with it), as it had made no difference on the earlier body (same refactor and helper names with and without, 2026-10-22). The four tests moved into that reference held execution 5 of 5 and evaluation, but stay in the body: the remedy lives in this skill and other skills route to it.
   After flattening the main path, four tests decide what moves, replacing the 20–30-line function trigger, which is now a soft signal in `navigation-cost.md` (2026-10-23). Sources: **level**, Beck's Composed Method and Martin's stepdown rule, bounded by Ousterhout's conjoined methods ("understanding the caller does not require understanding the callee", the criterion both accept in their written debate); **owner**, Ousterhout's information hiding plus the release idiom of each language: RAII in the Rustonomicon, `defer` in Effective Go ("the close sits near the open"), `with` in PEP 343, and react.dev's "An Effect can only do two things: to start synchronizing something, and later to stop synchronizing it"; **pure core**, Bernhardt's functional core, imperative shell; **consistency**, Ousterhout's chapter on consistency. Measured with behavior oracles (tests written before the runs and checked against mutants) on sidekyk `useContentSearch` (TS/React), sidekyk `process.rs::run` (Rust), and linqode `ExecStream` (Go, never used for tuning): the expected shape came out in 5 of 6 runs on the three cells; the one miss declared inner functions differently from the repository. Without the skill, Rust and Go met 3 of 5 shape conditions, and in both cases the release stayed on several exit paths. Behavior oracles passed in every run with and without the skill. Six other cells (discovery, evaluation, routing, exemption, nesting, four files) showed no regression. The 30-line trigger had split a lifecycle's setup from its cleanup; "interface with `start`/`stop`" listed as the first form gave three `kill` sites in Rust; "release written once, every exit path reaches it" gave one drop guard in 2 of 2 runs.
7. Work on the named files only. There is no three-file limit (removed 2026-10-24): with four named files the skill without it edited all four, suite green, nesting ≤2, and deferred the one left past the file-length trigger (1 of 1 on 2026-10-22, 1 of 1 on 2026-10-24).
8. Run the tests that cover the target with the repository's test runner; claim behavior preservation only when that test command passed. Codex's base instructions for gpt-6-luna say not to run tests unless the user asks; without these lines the test ran 1 of 3 on Termetrix and 0 of 1 on Go, with them 2 of 3 on Go and the third run said `tests not run` instead of claiming preservation. The **Checks** slot asks for the test command or `tests not run` with the reason: with the sandbox blocking the SSH tests, 1 of 1 said so and did not claim preservation (2026-10-24).
9. Route to `cf-placement` or `cf-architecture` when the request is theirs rather than local, and name that next step in the result when it is relevant. Moving code into another package goes to `cf-architecture` even when the request names the destination. A routed turn edits nothing: without that line the model named `cf-architecture`, opened it, and moved the package itself (linqode, 2026-10-06); with it 2 of 2 routed with no edits, and an explicit extraction now stops at the `cf-placement` route instead of running it in the same turn ("do not open it" had held 0 of 2 on 2026-10-04). On gpt-6.1-sol "when routing do not edit files" alone routed in one command and ended the turn (1 of 1, 2026-10-24). The description sends refactors or cleanups spanning several modules to `cf-architecture`: with "repository-wide refactors" only, a cleanup of one subsystem and its consumers opened `cf-cognitive` first 1 of 4 runs, skipped the target tree, and missed a consumer that classified log lines by their text; with the wider boundary it opened `cf-architecture` 5 of 5, and two local prompts still opened `cf-cognitive` (2026-10-26, Codex 0.164).
10. Keep cleanup bounded when a hard trigger's remedy belongs to another flow, but report the complete deferred finding required by the canonical navigation-cost contract. After the edits the measure runs again on every modified file; nested callbacks count as their own units. With only "apply the report/action separation", a 62-line function left in the edited linqode `logs.go` was deferred 0 of 3; with the command, 3 of 3 (2026-10-06).

Output slots: **Assessment** (with the test that decided each unit; filled in every run, while the same tests in prose in a reference were not applied), **Checks**, **Defects** (a real timeout defect in sidekyk `process.rs` named in every run with the slot, 4 of 4, and by no run without the skill, 0 of 1), **Deferred**, **Result**. **Scope** and **Changes** were removed on 2026-10-24 with no oracle affected in 12 cells. The slots use the pack's shared `## Output Format` list; a one-sentence inline form had filled them as well, and the list filled all five in order 2 of 2 (2026-10-24).

The two post-edit conditional routes — re-evaluating for a file split after each edited file, and handing a scattered local workflow to regrouping — were dropped with the merge. Trial material records a vague condition inside a pointer firing 4 of 9 times on identical input, and no bed ever exercised either clause.

A measurer saved in `.cflow/measure/` and reused was tried and dropped (2026-10-25). Reuse cut input to 258k and 209k against 473k and 592k for the run that wrote it, but the first run's definition is frozen for the project: a script that counted `else if` links as levels gave 1 of 3 target functions in both the run that wrote it and the run that reused it, and nothing invalidates a script written under an older skill text.
